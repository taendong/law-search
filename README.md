# 판례·결정 찾기

법제처 국가법령정보 Open API로 **판례, 법령해석례, 위원회 결정문, 행정규칙**을 키워드 하나로 함께 검색하는 단일 페이지 웹앱.
검색어는 결과 본문에서 형광펜·밑줄로 강조되고, 요지 필드가 없는 자료에는 키워드가 들어간 문장만 골라 발췌를 붙인다.

```
index.html      화면 전체 (검색·결과·강조 표시)
api/law.js      법제처 API 프록시 — OC 인증키는 여기 서버 쪽에만 존재
```

---

## 설치

### 1. OC 인증키 발급

[open.law.go.kr](https://open.law.go.kr) 회원가입 → **OPEN API 신청**.
발급되는 값은 이메일 아이디 앞부분(`@` 앞)이다.

신청 화면에서 **쓸 서비스를 각각 체크**해야 한다. 판례·법령해석례만 체크하고 넘어가면
위원회 결정문 검색이 조용히 빈 결과로 돌아온다. 최소한 다음을 함께 신청한다.

- 판례 / 법령해석례 / 행정심판례
- **위원회 결정문** (노동위·공정위 등)
- 행정규칙 (공정위 심사지침, 고용부 지침류가 여기 들어 있다)

### 2. GitHub 저장소 만들기

Git을 설치하지 않아도 된다. GitHub 웹에서 바로 만들 수 있다.

1. **New repository** → 이름 입력 → Public → Create
2. **Add file › Create new file** → 파일명 `index.html` → 내용 붙여넣기 → Commit
3. 같은 방법으로 파일명에 `api/law.js`를 입력한다. 슬래시를 치면 폴더가 자동 생성된다.
4. `README.md`도 같은 방식으로 추가

### 3. Vercel 연결

1. [vercel.com](https://vercel.com)에 **GitHub 계정으로 로그인**
2. **Add New › Project** → 위 저장소 Import
3. 빌드 설정은 그대로 두고 **Deploy**

### 4. 인증키 등록

Vercel 프로젝트 → **Settings › Environment Variables**

| Name | Value |
|---|---|
| `LAW_OC` | 발급받은 OC 아이디 |

저장한 뒤 **Deployments › 최신 항목 › Redeploy**를 한 번 눌러야 값이 반영된다.

끝. 이후로는 GitHub에서 파일을 고치고 Commit 하면 1분 안에 사이트가 갱신된다.

## 검색 대상 코드

`SCOPES` 배열(`index.html` 상단)에서 항목을 켜고 끄거나 추가한다.
`on: true`인 대상이 첫 화면의 기본 선택이다.

|---|---|
| `prec` | 판례 |
| `expc` | 법령해석례 (법제처 유권해석) |
| `decc` | 행정심판례 |
| `detc` | 헌재결정례 |
| `admrul` | 행정규칙 · 지침 |
| `law` | 현행법령 |
| `nlrc` | 노동위원회 결정문 |
| `ftc` | 공정거래위원회 결정문 |
| `eiac` | 고용보험심사위원회 |
| `iaciac` | 산업재해보상보험재심사위원회 |
| `acr` | 국민권익위원회 |
| `fsc` / `sfc` | 금융위원회 / 증권선물위원회 |
| `kcc` | 방송통신위원회 |

(허용 목록이 없으면 이 프록시가 아무나 쓰는 공개 프록시가 된다.)

## 설계 메모

**필드 이름을 하드코딩하지 않았다.** 법제처 응답은 대상마다 키 이름이 다르다
(`판례일련번호` / `안건번호` / `결정일자`…). 그래서 `normalize()`는 키 이름 패턴으로
제목·사건번호·일자·기관을 집어낸다. 대상이 하나 늘어도 파싱 코드를 고칠 일이 없다.

**본문 표시 순서**는 `FIELD_ORDER`가 정한다. 판시사항·판결요지·결정요지가 맨 위로 오고,
나머지 긴 텍스트 필드가 뒤따른다.

**강조는 이스케이프 다음에 넣는다.** `hl()`이 `esc()`를 먼저 부르는 순서를 바꾸면
법제처 응답에 섞인 태그가 그대로 실행된다.

**프록시 헤더.** 법제처는 `User-Agent`와 `Referer`가 없는 요청에 "사용자 정보 검증 실패"를
돌려주는 경우가 있다. `api/law.js`에서 넣어 준다.

**목록의 `id`는 일련번호가 아니다.** 법제처 목록 응답에는 화면상 행 번호인 소문자 `id`가
따로 들어 있다. 이걸 본문 조회에 쓰면 엉뚱한 문서가 열린다. `normalize()`는
`판례일련번호` 같은 `일련번호` 키를 항상 먼저 찾는다.

**원문 링크도 프록시를 거친다.** 법제처가 돌려주는 `상세링크`에는 OC 인증키가 그대로
박혀 있다. 그 링크를 화면에 노출하면 키가 샌다. 그래서 `/api/law?format=html&…`로
열고, 프록시가 `<base>` 태그를 심어 상대경로 자원이 깨지지 않게 한다.

## 자주 걸리는 문제

| 증상 | 원인 |
|---|---|
| 모든 검색이 `LAW_OC 환경변수가 없습니다` | Vercel 환경변수 등록 후 Redeploy를 안 했다 |
| 특정 대상만 0건 | 그 서비스를 OC 신청 때 체크하지 않았다 |
| `법제처에서 JSON 대신 다른 응답이 왔습니다` | OC 값이 틀렸거나(이메일 전체를 넣은 경우가 흔하다) 일시 장애 |
| 본문이 안 열림 | 그 자료가 원문을 제공하지 않는 경우. 원문 링크로 확인 |

## 확장 아이디어

- **AI 3줄 요약** — 요지 필드가 없는 위원회 결정문에 붙이면 효과가 크다.
  `api/summarize.js`를 하나 더 만들어 서버 쪽에서 호출하고, 결과에는 반드시
  원문 링크를 함께 노출할 것. 요약은 참고용이고 판단 근거는 원문이다.
- **선고일자 범위 필터** — `lawSearch.do`의 `prncYd=20200101~20251231` 파라미터
- **즐겨찾기** — 사건번호 기준으로 `localStorage`에 저장
